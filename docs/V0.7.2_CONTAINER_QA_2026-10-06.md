## Runtime and synthetic database acceptance

Full bootstrap and an independent read-only readiness check passed with all 34
tables, vector installed, no missing required columns and actual/expected head
`20261005_0016`. Native PostgreSQL 16 backup/isolated restore passed, along with
batch imports, the synthetic 7/15 detection-frequency fixture and NetCDF I/O.
Six HTTP checks passed: public startup/login/providers and 401 denial for protected
anonymous API and frontend proxy requests. This is synthetic runtime validation,
not approval of real ANEMONE/SST research demonstrations.

The first combined build failed before application validation: the synthetic
PostgreSQL initialization server briefly accepted a Unix-socket probe, then
restarted before the final probe. The retry changed only the verification step to
wait for TCP readiness, which observes the final server. It built the same
unchanged published source archive; source checks were already passed and were
not unnecessarily repeated. The maintained verifier receives the same probe
correction in the subsequent operations-record commit, which does not change the
published runtime tag or images.
