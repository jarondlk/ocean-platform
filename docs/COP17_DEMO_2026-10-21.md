## Implemented scope

- Settings expose ANEMONE eDNA and Satellite SST. Advanced model/retrieval
  controls and CTD/metagenome shortcuts are hidden in the demo profile.
- Current published dataset/assay combinations are selectable as complete
  setups. Fish-frequency and SST-comparison buttons apply the workflow,
  complete protocol identity, matching sources and published SST dataset.
  Buttons replace filters explicitly; unavailable selections are not repaired.
- Free-text remains editable. Free-text search clears transient workflow and
  analysis pins, leaving both supported evidence sources available.
- English/Japanese controls and preset questions are supported.
- Figures and result tables precede the full answer. Method definitions,
  scientific limitations, original citations and diagnostic details remain
  expandable; no published numbers or denominators are recomputed.
- Bounded English/Japanese paraphrases select exact rows for the two demo
  workflows without model inference or question rewriting. Unknown terms,
  changed scope, unsupported metrics and qualifiers fail closed. Existing
  execution checks retain source, cohort, publication and protocol constraints.

Professor examples E3-A/E3-B and E4-A/E4-B were recovered from the October 21
email attachments. Tests preserve the literal failed question wording and
compare exact result rows/citations against the successful aliases, using
synthetic fixtures. This does not substitute for authenticated deployment QA
against the real published dataset or the forthcoming demonstration scenarios.

## Data and authentication boundary

Create a separate service and an empty Enterprise Cloud SQL instance
`ocean-cop17-postgres` (1 vCPU, 4 GiB RAM; 15 GiB SSD, growth bound 20 GiB).
Use database `ocean_cop17`, independent credentials, signing secrets and demo
accounts. Production accounts, private history, audit/review rows and credentials
must not be copied. `scripts/prepare_cop17_snapshot.py` copies only the maintained
canonical scientific table registry. Source transactions are read-only, the
exact target is guarded, schema heads must match, every target table must be
empty, and sorted scientific row hashes/counts must reconcile before commit.

Serve immutable scientific files read-only from a controlled scientific snapshot.
Use a dedicated service identity and least-privilege grants. Runtime jobs remain
external; no production migration, ingestion, publication or traffic change is
part of this release. Preserve the scientific publication and original files.
Register `https://demo.oceaninfobio.com/api/auth/callback/google` as an additional
OAuth callback and use the demo origin for Auth.js and CORS. Keep production
origins/callbacks intact. Demo data and login access require real rehearsal.
