## Exact recorded-location counts

Free-text search now accepts “how many sampling area available,” “How many
sampling locations are available in ANEMONE eDNA?” and Japanese questions such
as “ANEMONEの採水地点はいくつありますか？” No example preset is required.
With the default ANEMONE + SST sources, the count is explicitly ANEMONE
coverage; SST pixels, dates and regions are not added to field positions.

The unchanged snapshot has **216 distinct reported coordinate pairs** after
excluding explicitly classified controls. This covers 3,155 source occurrences:
3,154 have valid coordinates and one has missing coordinates. All remaining
control classifications are unknown; none is assumed environmental. The
coordinate-bearing records are marked `provider_grid_unconfirmed`, so the
answer describes recorded positions and does not claim verified physical sites
or named sampling areas.

SQL counts exact finite, in-range latitude/longitude pairs without rounding or
assay joins, respecting the selected source filters. Repeated sampling dates
and alternative methods do not inflate position counts. Explicit control or
sample-kind filters are preserved. Unsupported geography, dates, ecological
qualifiers, physical-site identities, named areas and ambiguous data-point units
produce deterministic clarification instead of a total from retrieved examples.
ANEMONE-disabled requests explain which source to enable. New answers use a
versioned immutable aggregate citation and no model invocation. Historical v1
aggregate citations remain readable alongside the new v2 location receipts.

To avoid repeatedly hashing the same complete source cohort during a rehearsal,
the COP17 profile can reuse a verified immutable v2 location receipt. Reuse
requires the exact normalized effective filters (including the control policy),
`recorded_locations` metric, empty grouping, and all three publication heads
(`anemone-canonical`, `edna-canonical`, `edna`) with matching generation IDs and
manifest SHA-256 values. The retained payload is rehashed and its embedded scope
and publication values are verified. The heads and ready GCS retrieval pointer
are checked again outside the initial read snapshot before the answer is served.
A new cohort still computes the complete ordered source/input fingerprints.

This relies on the demo's scientific tables remaining immutable while their
publication heads are unchanged; the runtime role has SELECT-only scientific
access. Manual unpublished edits to scientific rows invalidate the assumption
and require republishing before retained counts are served. Reuse is disabled
outside the COP17 profile. Filtered cohorts never reuse a wider catalogue count.

The first five optimized exact-count requests took 0.317–2.699 seconds at the
Cloud Run request boundary. A later repeat took 12.811 seconds, so a response
below ten seconds is not guaranteed. The receipt retains all rehearsal timings.
