# Context Catalogue v1 contract

C08 freezes `context-catalogue-v1` for Python producers and the new v1 browser.
This is a transport/fixture contract. Storage, snapshot sealing, real source
adapters, authenticated endpoints and UI activation belong to later components.
Existing legacy APIs, source aliases and the accepted P00 runtime are unchanged.

## Authoritative files and generation

- [Python models](../../../schema/context_catalogue.py) own fields, vocabularies and validation.
- [JSON Schema](../../../schema/context_catalogue.v1.schema.json) is generated by [export_context_catalogue.py](../../../scripts/export_context_catalogue.py).
- [Browser types/schema](../../../frontend-v1/src/catalogue-contract.generated.ts) are generated by [export_catalogue_types.py](../../../scripts/export_catalogue_types.py).
- [Shared wire examples](../../../schema/context_catalogue_examples.json) are generated by [export_catalogue_examples.py](../../../scripts/export_catalogue_examples.py).
- [Browser boundary](../../../frontend-v1/src/catalogue-contract.ts) validates unknown JSON, enforces semantic invariants, and projects an explicit P00 view while retaining the full wire object.
- [Synthetic oracle](../../../schema/context_catalogue_fixtures.py) supplies local fixture access, traversal, counts and descriptive receipts. It imports no application configuration or real data.

Run all three exporters with `--check` to detect drift. Python tests enforce
all generated artifacts, and frontend tests consume the same valid/invalid cases.
JSON Schema describes structure; semantic validators additionally enforce count,
cursor, scope, authority and completion relationships. It is not a replacement
for those validators. The browser adds no package dependency.

## Identity, hierarchy and scientific scope

The five fixed roots are Data, Analyses, Statistics, Metadata and Relationships,
with IDs `root:data`, `root:analyses`, `root:statistics`, `root:metadata` and
`root:relationships`. Every other canonical ID is independent of title, parent,
path, snapshot or documentary rank. Facet/related edges refer to existing IDs;
they do not create another scientific object. Root identity is fixed and roots
have no parent. Dataset sections are, in order, Overview, Tables, Coverage,
Methods, Provenance and Related.

Wire source families reuse `ctd`, `metagenome`, `remote_sensing` and
`edna_metabarcoding`. The existing positive alias registry is exported to the
browser; `SST`, `eDNA` and other registered aliases are normalized explicitly
before producing canonical wire fields. No legacy alias or old API is removed.

Every scoped envelope embeds the existing validated `EvidenceScope`. The new
wire boundary rejects padded filter text and uses explicit ISO calendar dates
or timestamps with seconds, optional microseconds and optional timezone. UTC
bounds must fit years 1–9999, including a date-only end's exclusive boundary.
The older scope/date helpers retain their existing API. A node's source must
be enabled in its scope. Existing C01 `publication-scope-v1` receipts remain a
separate question/publication compatibility result; catalogue query readiness
cannot establish that compatibility. Completed results cannot override an
incompatible or unresolved supplied C01 receipt.

Source descriptors preserve CTD cast/depth sampling and units; SST product,
version, spatial/temporal resolution and regional role; metagenome assignment
method, abundance denominator and omitted-taxon meaning; and eDNA protocol,
assignment, sample classification and control status. Unknown control status can
remain null. Candidate relationship proximity is not verified physical identity.

## Counts, listings and current access

`CatalogueCount` declares known/unknown state, entity, denominator and
`complete_scope` basis. Known zero is exactly zero. Unknown requires a reason
and no value. Counts and cursor offsets use exact integers through 2^53−1;
booleans, fractions, negatives and larger values are rejected. JSON integral
`1.0` and `1` have the same wire meaning. Integral result/parameter values outside
the exact browser range must be encoded explicitly as text, never silently
rounded. Nonfinite, cyclic or excessively nested producer values are rejected.

A listing request binds snapshot, scientific scope, parent, filters, ordering,
page size, effective-access binding and permission revision. Default pages have
100 objects and the maximum is 500. Ordering is case-sensitive Unicode code-point
order; title means English title. A final canonical-ID tie-breaker is required.
Each response reconciles returned count, unique items, snapshot, ordering,
complete-scope total and continuation. Preview truncation, source completeness
and query completion are independent. A complete inventory query may still
have another page; incomplete source observations do not imply a failed query.

The fixture oracle's parent listing means immediate children; descendant summaries
traverse canonical edges and deduplicate IDs. Global filters/search reach the full
permitted inventory independently of documentary rank. C14 must preserve these
semantics with a real service. Unknown or unavailable sources must not be rendered
as known empty populations. Private Workspace objects may have node envelopes,
but cannot appear in global catalogue listings or published analysis membership.

The cursor is an encoded, versioned context hash plus offset. Its hash binds the
full normalized request except the cursor itself, including page size and current
access. Coordinate IEEE-754 byte encoding avoids Python/JavaScript decimal
spelling differences. **It is a fixture/reference continuation token, not a signed
authorization capability.** C14 must authenticate/recompute access before counts,
metadata, caches and pages, and decide its production token protection. A hash
must never grant access or preserve permissions after revocation.

Fixture access is supplied by the trusted local test caller. New list calls
re-evaluate it and suppress denied nodes, ancestors and related-target IDs.
The 100,000-dataset traversal freezes one supplied fixture view for efficient
reference slicing; it does not prove per-request live revocation, cache safety,
service throughput or production performance.

## Operations, receipts and origins

`OperationRequest` and descriptors name versioned operations and preserve scope,
input IDs and parameters. C08 defines no dispatcher. A syntactically valid
operation ID or a parameter object grants no execution capability; C14/C19 must
use registered permitted operations and validated source-owned parameters.
Receipts retain input hashes/generations, operation version, scope, authority,
provenance, counts, completeness and content identity. Query tables reconcile
unique column keys, row keys and receipt row counts. A bounded preview does not
change the full synthetic input manifest or content hash.

Ingestion, publication, scientific approval, query readiness and embedding
readiness are independent lifecycle fields. Published authority requires a
published lifecycle, but publication does not establish scientific approval.
Queryability is independent of embeddings. Experimental results remain private
and experimental; no automatic promotion to global published analyses occurs.

Transfer-origin fields retain source system/object/snapshot/generation,
content hash, schema/operation versions, scientific qualifications, access
conditions and authorization reference. `live_dependency` is strictly false.
These fields describe provenance; they do not fetch legacy data or authorize a
transfer. C09 owns real manifest/sealing/import contracts; actual transfers and
withdrawal operations remain separately selected work.

## P00 reconciliation and downstream work

C08 adds one opt-in `catalogueAdapterV1` boundary. It does not change the existing
fixture adapter, models, state, local storage or UI. Missing/malformed backend
input yields unavailable, and stale access yields revoked with no cached total
or projected membership. No synthetic production fallback is introduced.

The P00 projection keeps canonical IDs, source labels, titles, purposes and
related links, while retaining the full validated wire contract beside it.
Root/directory maps to P00 directory; table/statistic/metadata/relationship maps
to P00 reference; dataset/analysis/workflow keep their kinds. This projection
alone cannot render all scientific qualifications: C15/C16 must use the retained
contract for lifecycle, authority, provenance, scope and completeness. Existing
P00 boolean completeness and page-number navigation are provisional; real UI
must use the independent fields and bound cursors. Prototype IDs and local
synthetic investigations must not silently become real persisted records.

C09 consumes identities/scope/origin contracts for snapshots; C10–C13 provide
scientific adapters and sections; C14 implements authenticated services; C15/C16
adopt the boundary in the real UI. Real administration/feedback service ownership
remains a separate integration planning item. C08 starts none of those components.
