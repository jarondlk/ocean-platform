# C22 independent acceptance preparation

Prepared after formal selection, against the C22 experiment contract. This is a test plan, not an acceptance result. Shared DTO names and route actions must come from the actual new schema. No application source, tests, services or executor were changed or run by this preparation.

| Boundary | Adversarial cases and observable result |
|---|---|
| Current private ownership | Prepare/revise/approve/dispatch as the current researcher and as an admin approving their own proposal. A different researcher and an admin targeting another owner's ID must receive an owner-private failure. Fresh suspension, role/permission change or source withdrawal must supersede a previously accepted request or approval. |
| Exact context and revision | Change each investigation/conversation/revision/snapshot/payload field independently; reject cross-context joins. Change the CAS head or proposal revision after reading; the old revision remains immutable and approval authority cannot transfer. |
| Five approval hashes | Independently change proposal, exact UTF-8 Python, input-manifest, environment descriptor and resource hash. No mismatch may reserve capacity, insert dispatch outbox or reach the fake executor. Unknown environment IDs and request-supplied publication/eligibility authority must fail. |
| Scientific cohort | Exercise each actual source selector and every C17 pin, including dataset, method, date, spatial, taxon/rank and published-analysis restrictions. Unsupported constraints and ambiguous cohorts remain explicit failures. Exclusions cascade only through actual source-owned foreign keys. Proximity, reviewed matching and shared labels cannot become verified physical pairing. |
| Frozen machine export | Preserve integers beyond JavaScript's safe range, finite floats, nulls, Unicode, dtype, row identity/order, units and qualified denominators in private canonical machine bytes. Different presentation page limits cannot change the full cohort. Human CSV uses the separate C07 policy and must not replace or modify machine bytes. |
| Integrity and size | Tamper each staged file, manifest, sidecar, source object or publication witness after preparation and after approval. Account for every file and manifest byte at the 256 MiB boundary; reject the first byte over it without sampling. Output/resource caps and unsupported extra fields fail strictly. |
| Durable idempotency and reservations | Same key and exact request recover the same operation/reservation/envelope. Same key with changed body conflicts. A different key cannot dispatch the same approved revision twice. Actual concurrent dispatch admits at most one active proposal per owner and two globally, with reservation and outbox in one transaction. |
| Unknown dispatch outcome | Lose the executor acknowledgement, crash after reservation or expire a lease; the reservation and dependency protection remain. A retry cannot infer stopped execution or release capacity. Only the defined C23 completion/termination proof may support later release. |
| HTTP boundary | Check fresh dual research/read plus export/approval permissions before reading an invalid body. Reject duplicate JSON keys, nonfinite values, invalid UTF-8, unsafe cursors, extra authority/owner fields, query parameters and oversized streamed bodies. Match every response to the requested original context/revision; sanitize internal exceptions and retain no-store/nosniff. |
| No execution or publication | Store Python containing an observable execution sentinel and inspect it as inert text; no request may import/evaluate it, make provider/network calls, install packages, write published registries or acquire real data. The explicitly injected fake executor records an immutable envelope only. |

Pure DTO/canonical tests will live in `tests/test_research_experiment_contracts.py` once the shared schema is available. Real-service, PostgreSQL and HTTP probes must use the actual new service and explicitly synthetic sealed C09/C13/C17 fixtures. Independent review must distinguish these local software checks from real execution containment, real publication permission, independent scientific approval and deployment acceptance.
