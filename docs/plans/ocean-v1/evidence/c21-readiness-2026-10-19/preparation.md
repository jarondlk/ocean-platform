# C21 preparation while C20 delivery is pending

This is read-only interface preparation, not C21 selection, implementation or
acceptance. C21's formal prerequisites are C05/C06/C07/C13/C19/C20. Reconcile the
accepted sources and immutable supersession chains after C20 is delivered on
overhaul with source-bound hosted CI; take a fresh protected-file/evidence baseline.

The actual C20 run rows are terminal-immutable. Its production result is literally
null in both Python and TypeScript, and runtime synthesis remains unavailable.
Add separate versioned immutable answer/evidence records and APIs rather than
rewriting C20's controller result or silently changing its seven-action envelopes.
Associate records with owner/run/input version, conversation and frozen context.
C17's artifact_resolver(user,reference) -> RetainedArtifactBinding is the existing
explicit attachment integration point. Legacy Chat history and evidence links
remain on their existing site.

C19 closes its180-second active budget before returning. C21 needs a durable
accounting design before dispatch: derive any remaining shared time/call allowance
from C20's closed high water and retain separate synthesis reservations/leases.
Status/evidence reads cannot initiate model work. An explicit linked continuation
is a separately granted segment; automatic retry cannot reset the original limit.
Provider-independent fake-model acceptance is authorized; live models are not.

Observation.full_payload_sha256 hashes the canonical C14 response, while
ResearchRunPayload.sha256 hashes the whole private replay outcome envelope.
Validate the two domains separately. Reconstruct verified checkpoint.full_payloads
and typed observations, including derived inventory-union payloads. A child that
reuses only a parent inventory prefix may need the retained parent chain; do not
assume every full evidence blob is copied into the child's latest checkpoint.
Recheck owner, binding, current source policy and immutable execution manifests.

Receipts retain operation/version/parameters, complete input identities and hashes,
scope, result hash, authority, completion and qualifications. Keep large tables
outside public events and return bounded previews/pages. Unknown coverage is not
zero, and preview length is not the exact input/result population. Published,
exact descriptive, documentary and experimental authority remain distinct.
Only supplied evidence aliases may be cited; syntactic citation validity cannot
establish factual or scientific correctness. C06 completed-generation checks and
C07 safe CSV serialization remain mandatory boundaries.

Existing ArtifactStore is an immutable bounded blob utility, not an owner/policy/
hold-aware v1 evidence service. Existing db.retention deletes legacy Chat records;
C17 retains context references and inherited holds. Add explicit independent-v1
storage/reopening/retention with tested hold and withdrawal races. Documentary RAG
must use an explicitly scoped v1 provider; legacy retrieval's global/current-store
defaults are not an authorized fallback or source acquisition path.

Possible owned interfaces are EvidenceReceipt, EvidenceService.retain/open/page/
export/resolve_attachment, SynthesisPack, SynthesisService and a separate frontend
evidence client. UI acceptance needs answer cards, retained citation navigation,
table pagination and scope/authority/limitation disclosures, with current-identity
invalidation and safe downloads. C26 remains the assembled system acceptance gate.

Required cases include changed publications, withdrawn/revoked access, holds and
cleanup races, payload tampering, unseen citations, incomplete/truncated generation,
unknown versus zero, preview versus totals, unsupported relationship wording,
experimental authority and old-link compatibility. No missing external target
blocks synthetic local implementation once C20's actual delivery gates pass.
Real transfers, scientific reviews and GCP configuration/deployment remain explicit
external gates. No new component is selected by this preparation document.
