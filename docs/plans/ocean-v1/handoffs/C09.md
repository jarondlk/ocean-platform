## Accepted implementation

`catalogue-snapshot-v1` hashes canonical manifests and exact immutable export
bytes, binding source/dataset/object identity, publication/classification/
relationship/operation generations, schema/method versions and provenance.
The local store uses bounded explicit v1 paths and one locked atomic control
state for latest, references, holds, revocation, retirement and audit records.
Sealing registers immutable bytes without promoting latest. Latest uses a
separate generation and conditional update after integrity/current-policy checks.
Historical reads verify original bytes and current access, without substitution.

Registered source exporters run in a bounded read-only REPEATABLE READ PostgreSQL
transaction. A final bounded SHARE lock on the dedicated generation table
rechecks all heads, blocking updates/inserts/deletes through seal/promotion.
Rollovers retry within the configured budget or fail without becoming latest.
Sources must update their generations in the same transaction as their data.
Whole enabled source families are captured; unsupported scientific filters and
analysis IDs fail before DB connection. C10–C13 will query/filter frozen exports.

Frozen CTD, Kraken/MetaEuk, SST coverage and canonical eDNA/classification exports
provide eight artifacts/twelve rows, executable export registrations, versioned
JSON Schema and portable byte examples. Old manifests reopen after a newer seal;
computed changes identify added/removed/replaced export identities. Embeddings
are absent from capture and structured-read readiness.

`catalogue-transfer-v1` binds destination, original snapshot, exact hashes/counts,
source/schema/operation versions, qualifications and authorization reference.
Synthetic imports verify trusted current gates, quarantine exact bytes, reconcile
again and seal an independent origin-retaining manifest. They never promote
latest, open an origin URL/path, or fall back to another store. Chained copies
are rejected until a typed multi-hop lineage contract exists.

## Limits and recovery

Cleanup is logical retirement; `physical_deleted_count=0`. Latest, held and
referenced snapshots survive; actual physical garbage collection is deferred.
The bounded local control ledger is a local implementation, not an unbounded
production catalogue. Trusted callers must supply current authorization and
eligibility. Source withdrawal needs an operator policy mapping origin IDs to
otherwise independent copies before any real transfer.

PostgreSQL and files do not share an atomic commit. `SnapshotCommitUncertain`
or `CapturePublicationUncertain` carries the proposed revision/snapshot/pointer;
inspect current state before retrying. Confirmed immutable seal state may remain
after failed publication/import; never claim rollback or automatically overwrite
a competing latest. Capture releases the database before later model reasoning.
