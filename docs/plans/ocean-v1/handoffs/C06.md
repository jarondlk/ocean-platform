## Generation-result v1

`model_runtime.py` exposes frozen `GenerationResult` and `GenerationUsage` through
`chat_result` and `structured_chat_result` for both providers. The stable fields are:

| Field | Meaning |
|---|---|
| content | Generated text, including partial text for explicit result inspection; omitted from repr/diagnostics |
| provider, model | Actual selected runtime/model identity |
| status | completed, output_limited, refused, failed or unknown |
| finish_reason | Original safe provider finish token; None if absent/malformed |
| elapsed_seconds | Monotonic measured operation duration, including existing retry/backoff |
| usage | Optional frozen input_tokens/output_tokens/total_tokens; individually unavailable counts stay None |
| max_output_tokens | Selected known cap, otherwise None |

`diagnostics()` returns metadata only, rejecting unsafe free-form labels and
credential URLs. `require_completed()` returns only completed content. Other
outcomes raise provider-neutral `GenerationError` with the immutable result and
safe diagnostics. Output limits raise its `ModelOutputLimitError` subtype; the
existing Vertex message/three-key error diagnostics remain compatible. New
consumers use the full `error.result.diagnostics()` witness. No transport exception
text, prompt or generated content enters public diagnostics or exception chains.

Existing string-returning `chat` and `structured_chat` signatures remain intact
and delegate to this same strict guard. Production has no bare-string completion
fallback. Test-only completed fixtures explicitly attest synthetic stop metadata.

## Provider mappings and boundaries

Central normalization serves both generation methods. Ollama stop and Vertex STOP
with nonempty text complete. Explicit unfinished/malformed Ollama done contradicts
stop and remains unknown. Missing finish metadata never completes. Ollama length
and Vertex MAX_TOKENS are output_limited; refusal/safety/block reasons are refused;
known provider failures and malformed/empty responses are failed; other finishes
are unknown. Unknown/malformed Vertex block feedback overrides even candidate STOP.
A valid JSON string never overrides an incomplete provider status.

Only provider-reported nonnegative integer usage is retained. Ollama uses
prompt_eval_count/eval_count; Vertex uses prompt_token_count/candidates_token_count;
reported total_token_count is optional and not derived. Missing, negative, boolean
or malformed counts do not become invented zeros. A real zero remains zero.

Ordinary Vertex retains its existing bounded transient-status retry policy;
structured Vertex remains one attempt. Ollama still makes one request. No
controller retry is added. Transport failures become safe failed results, including
metered callback failures; the existing request budget still blocks provider calls.
BaseException cancellation propagates. Existing provider configuration/options,
model choices, embed/embed_batch methods and embedding identity remain unchanged.
Four provider embedding methods are AST-identical to the base.
