## Chosen transaction contract

Cleanup uses the complete cutoff, terminal-status and unheld predicate in the
actual DELETE, returning IDs of parents truly removed. Feedback and parent JSON
evidence deletion stay transactional. Hold updates use UPDATE/RETURNING on the
same parent row. A hold committed first protects it; a deletion committed first
causes a later hold to return not found. Reports count actual removals and audits
share the commit boundary. Dry-run counts remain observations, not reservations.

Read [PostgreSQL Read Committed documentation](https://www.postgresql.org/docs/16/transaction-iso.html)
and [SQLAlchemy ORM DML RETURNING documentation](https://docs.sqlalchemy.org/en/20/orm/queryguide/dml.html)
to confirm row-update waiting and predicate rechecks.
The integration fixture must use a dedicated explicit test URL, verify database
identity and loopback host, and isolate each test's schema before any deletion.
