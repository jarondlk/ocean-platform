OCEAN v1.0.0 Architecture Overhaul

The proposed overhaul turns OCEAN into a research workspace built around discoverable data, explicit investigation scope and retained evidence. It preserves the legacy system’s scientific caution while making the research process easier to understand, inspect and reproduce.

Why this approach is stronger

  1. More complete discovery. The legacy general retrieval path is capped at k=25, although it also has exact aggregate and published-workflow routes. The v1 plan separates complete catalogue inventory from relevance ranking: ranked search remains useful, but cannot silently define what data exists. P00 demonstrates full matching counts and pagination over its small synthetic inventory; production-scale validation comes later.
  2. Research continuity and reproducibility. Named investigations contain separate conversations, recoverable drafts and an inspectable workspace. Adding context and restricting scope are different actions. Runs retain their snapshot and context revision, and refreshing creates a branch rather than rewriting old evidence. Receipts and exports make the inputs, limitations and results easier to review.
  3. Clearer scientific meaning. CTD profiles, regional SST, metagenomic libraries and eDNA occurrences retain their different observation units and qualifications. Unknown coverage is distinct from zero; candidate relationships do not imply physical sample identity. Published references, available workflows and experimental results keep separate authority labels.
  4. More controlled execution. The planned backend adds typed catalogue operations, bounded exploration, explicit partial completion, durable progress/recovery and version-bound experiment approval. Isolated execution is intended to prevent research code from reaching credentials, the host or external networks. These capabilities are future implementation gates, rather than claims about the local demo.
  5. Less friction for people using the system. The research-first interface exposes account type and role, uses concise labels and baby-blue accents, supports English/Japanese and light/dark themes, and gives feedback, exports and administration clear places. The admin prototype retains the legacy’s Users, Feedback, Pipeline, Database, System and Debug concepts and adds catalogue/retention visibility and reversible controls.
  6. A safer rollout and clearer maintenance boundaries. The v1 plan uses separate infrastructure, storage, credentials, sessions and queues, with explicitly approved data copies. This allows validation and rollback without a main-domain cutover or automatic import of legacy accounts/history. The current P00 frontend is already separate from the legacy code path.

UX verification completed

The prototype was reviewed against Nielsen’s usability heuristics and selected WCAG 2.2 AA criteria, using source review, keyboard walkthroughs and rendered browser measurements. Checks covered research, catalogue/map, About, Feedback, dialogs and Administration, including 320px reflow, Japanese labels and both themes.

  • Corrected small-text contrast, increased tiny metadata labels to at least 11px, strengthened input/focus boundaries and ensured measured controls meet the 24px minimum target size.
  • Verified mobile drawer entry, focus trapping, Escape and focus return; dialog transitions and destination focus; visible panel focus; and completion/status announcements.
  • Fixed two admin workflow problems: scheduling no longer hides the new job under a filter, and a demo check no longer discards unsaved settings.
  • Seventeen rendered checks found no remaining sampled text-contrast failures or undersized control bounds. TypeScript, 27 focused tests and the static build passed; captured browser warning/error logs were empty.

Status: P00 is a working, locally persisted prototype with synthetic data and simulated roles, jobs and analysis. This is a scoped usability/accessibility verification, not a full WCAG conformance certification or a study with representative end users. Real authentication, backend durability, scientific acceptance, sandbox containment and deployment remain future gates. Better model accuracy, latency and cost must be measured against matched legacy inputs; they are not established by these screenshots.
