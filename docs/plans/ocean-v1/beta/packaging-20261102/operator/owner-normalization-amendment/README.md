# Fixed empty beta database owner normalization

The explicit `normalize-owner` stage changes only `ocean_v1_beta` from owner `cloudsqlsuperuser` to `postgres`. It uses the existing exact project, SQL connection, API/operator revisions, principal DSN and four CLI confirmations. It requires no application passwords. The existing operator supplies one explicit transaction and the usual proxy finalizer.

Before its only DDL statement, the stage checks actual database/current/session identity; obtains the same scoped advisory transaction lock as bootstrap; refuses existing `ocean_v1_` roles, public relations/functions/migration head, unexpected user schemas, or any extension set except exactly `plpgsql`; requires the current database owner to be `cloudsqlsuperuser` and public schema owner to be `pg_database_owner`; and requires the existing actor's CREATEDB attribute and inherited old-owner `USAGE` privileges. No grant, role membership or privilege elevation is added to acquire that authority.

The sole DDL is identifier-composed `ALTER DATABASE ocean_v1_beta OWNER TO postgres`. The stage verifies the database owner is now `postgres` and the public schema owner is unchanged before commit. A failed precondition issues no ALTER, and a failed postcondition raises inside the transaction so it rolls back. Already-normalized or differently owned targets are refused for inspection rather than silently accepted. Ordinary operator readback then observes the committed target from its standard subsequent connection.

The ownership transfer intentionally transfers database-owner rights and PostgreSQL's associated owner ACL metadata. The stage issues no separate GRANT/REVOKE, role, extension, schema-owner, password, application-object or data SQL. `pg_database_owner` continues to own public and follows the database owner; no public-schema ownership rewrite is needed. These are ordinary PostgreSQL ownership rules, still subject to actual managed execution. [ALTER DATABASE rules](https://www.postgresql.org/docs/16/sql-alterdatabase.html), [pg_database_owner](https://www.postgresql.org/docs/16/predefined-roles.html)
