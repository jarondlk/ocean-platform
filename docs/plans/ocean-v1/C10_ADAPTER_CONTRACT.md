# Frozen CTD and metagenome adapters

C10 implements local source-owned adapters over verified C09 snapshots. It reads
explicit immutable metadata and Parquet bytes, and supplies canonical C08 nodes,
listings and operation results. This checkpoint contains no authenticated endpoint,
UI integration, acquisition, real data transfer, scientific publication or cloud
configuration. Missing inputs have no fixture, model, ranking or legacy fallback.

## Explicit frozen inputs

Each dataset has a JSON metadata artifact with role `dataset_metadata` and one
Parquet object per retained table. Metadata binds dataset/source/family/collection
identities, localized descriptions, source semantics, actual date precision,
qualification, methods and every supported table role. A missing table must have
an explicit unavailable descriptor, reason, null object/count and unavailable
completeness. Empty retained tables have an exact zero row count. Partial/unknown
retained tables remain distinct from both states.

CTD roles are `casts` and `depth_observations`. Casts retain `cast_id`, sample
label, collection date, bay and station. Depth records retain `observation_id`,
`cast_id`, declared depth and numeric measurements with explicit units. The
source declares `positive_down` or `signed_source`; signed depths and negative
measurement values are preserved. The descriptive sampling contract never
creates an expected cast schedule.

Metagenome roles are `collections`, `run_qc`, `kraken_abundance`,
`metaeuk_abundance` and `ranked_taxa`. Collections retain library identity, sample
label, collection dates and explicit method-coverage flags. Runs retain their own
identity/date and any declared sequencing/QC columns. Complete normalized cells
retain library, taxon, assignment method, rank and abundance. Method names, units
and abundance denominators belong to the table; no combined abundance across
methods is invented. Numeric/count columns require units or counting entities.
Complete tables must contain the explicit library/taxon cell grid for their
registered method-covered libraries. A cell may be null; an absent cell cannot
be silently filled with zero.

The source owner must explicitly map approved normalized input fields to these
versioned schemas and declare units, identities and temporal precision. Existing
legacy preprocessing column names, timestamp objects and top-ten JSON are not
silently imported or reinterpreted. `dataset_exports(metadata, frames,
generation=...)` freezes explicit caller-supplied frames into canonical Parquet
and C09 descriptors. This does not grant permission to copy any real artifact.

Frozen column order/types, nonnull keys, unique identities, foreign keys, row
counts, methods, ranks, coverage flags and finite browser-safe numeric values are
validated. Source-qualified dataset/cast/library identities remain distinct even
when sample labels coincide. Dataset, collection and table IDs must not collide
with each other or reserved roots/source directories. Related links reference
existing permitted canonical IDs and never create inventory membership.

## Bounded parsing and export registration

Readers verify C09 hashes/current access before interpreting bytes. There are at
most 64 declared primitive columns per table, 2,000,000 decoded rows across C10
inputs in one snapshot, and a 512 MiB Arrow/footer decode budget. Exceeding these
bounds fails explicitly; no records are truncated to meet a budget. C09's own
object/manifest/control bounds also apply. These are input/decode bounds, not a
measured process-RAM or production-throughput guarantee.

The canonical writer uses Parquet plain values, Zstandard compression and no
pandas index metadata. Readers reject dictionary/prefix/other expanding value
encodings before decoding; their compact encoded footer sizes cannot prove a
bound on expanded strings. Supported encoding metadata is PLAIN/RLE/BIT_PACKED.
Other source Parquet encodings require an explicit canonical export step, never
a read-through to an original source path.

`frozen_export_requirement(metadata, frames, source_generation=...)` registers
one frozen dataset. `frozen_source_requirement([(metadata, frames), ...],
source_generation=...)` registers every explicit dataset owned by one source and
family. Registration freezes bytes immediately. Its exporter checks its deadline
and requires `heads.source_generation(source_id)` to equal that exact generation.
A changed head fails and requires rebuilding the registration; old bytes cannot
be relabelled with a fresh head. This helper does not perform SQL discovery or
claim to make arbitrary caller frames transactionally consistent. Source owners
must provide exact bytes from the named generation. C09 retains its final
head/lock/promotion protocol when these registrations participate in capture.

C09's registry still covers four families. C10 supplies two source families only;
disabled future-family registrations must remain explicit and unavailable until
implemented. No fixture callback is an implicit replacement for a real exporter.

## Read, scope and access APIs

Construct `FrozenCatalogueAdapter(store=explicit_v1_store, access=AdapterAccess(
binding, revision, eligible_callback))`. The callback receives snapshot ID and an
isolated metadata copy, and must return literal True for current dataset access
and eligibility. A grant covers that complete dataset; row-level authorization
and role/session enforcement belong to later service integration. Scientific
filters do not substitute for authorization. Every call rereads the requested
snapshot and rechecks policy; there is no cached result or latest substitution.
Metadata cannot grant publication or scientific approval: nodes/receipts remain
descriptive, with unpublished/not-reviewed lifecycle states.

`list(ListingRequest)` and `open(id, ListingRequest)` return C08 canonical nodes.
`dataset_count(request)` counts distinct matching permitted descendant datasets,
independent of page size and related links. Listings use C08 context-bound cursors
and stable ordering. `inspect(dataset_id, request)` returns the node plus Overview,
Tables, Coverage, Methods, Provenance and Related sections. Missing/denied direct
IDs have the same access error, and denied related IDs are omitted.

Use only enabled CTD/metagenome selections with the existing EvidenceScope.
Malformed filters fail explicitly. Requested sources must actually have captures,
not just enabled manifest flags. C10 requires whole-source snapshot exports;
row filtering occurs after capture. C09 snapshots with scientific filters are
unsupported here. Bay/station/sample filters apply to source anchors before
measurement/run joins and pagination. Collection dates govern scientific time
scope; sequencing dates do not stand in for collection dates.

Date-only/day and zoned instant filtering follows the existing shared UTC
comparison contract. Month/year periods must be wholly covered by a requested
time interval; a partially overlapping coarse period is unavailable for an exact
cohort. Unknown dates under a temporal filter also make the exact result
unavailable. Uniform precision or explicit per-record `date_precision` for a
`mixed` dataset is retained in table/coverage results. No first-of-month collection
day, timezone or expected sampling gap is fabricated.

## Exact operations and receipts

`query(OperationRequest)` accepts one canonical dataset ID and version `c10-v1`:

| Operation | Parameters and semantics |
|---|---|
| `c10.table` | Required table; optional taxon, limit 1–500, offset; stable source-row IDs |
| `c10.count` | Required complete table; optional taxon; complete matching row count with entity/denominator |
| `c10.summary` | Required complete table and numeric column; optional taxon; observed/missing/zero counts and min/max/mean with source units |
| `c10.coverage` | Collection-period counts of casts/libraries; retains actual precision and an undated bin; no inferred expected schedule |

Unknown tables/operations/parameters, stale access contexts and invalid offsets
fail. A declared missing table or unsupported complete operation yields an
explicit unavailable C08 result with unknown total, no fabricated zero and no
rows. Ranked tables can supply partial previews, but never exact normalized
counts/means. Missing units/abundance denominators/ranks prevent scientific
summaries. `c10.contigs` is explicitly unavailable on metagenome nodes.

`AdapterResponse.result` is the unchanged C08 QueryResult; the wrapper adds frozen
table schema, offset/next_offset and qualifications. Count/summary results contain
one aggregate row, so receipt.total_rows counts aggregate output rows; the count
value itself carries the source entity/denominator. Table pages report complete
scoped row totals only for complete sources. A final page may still be a truncated
preview because preceding result rows are omitted; next_offset independently
indicates remaining pages.

Every receipt binds snapshot, scope, operation version, exact input IDs/hashes/
generations, parameters and full result content hash. Full computation precedes
preview slicing, so content hashes and complete totals do not change with preview
size. A taxon absent from a ranked summary is unknown. An absent normalized taxon
has zero retained matching cells and no invented measured abundance; explicit
zero cells and null measurements retain separate observed/zero/missing counts.
Imported C09 copies retain original transfer origins in inspection provenance.

reference aggregates, source collisions, all pages/sections, coarse/mixed dates,
missing/partial tables, zero/missing/ranked omission, malformed/corrupt inputs,

service/tools and later UI integration remain separate components. C02 real

receipts; legacy routes, normalization outputs and publication heads are unchanged.
