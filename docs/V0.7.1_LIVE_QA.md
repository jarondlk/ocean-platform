- [ ] Source choices and available source-owned filters load. With only SST/eDNA
  enabled and k=8, ask: “Where do ANEMONE sampling dates and locations overlap
  with available SST observations”. Expect 4+4 supplied, `overlap_unverified`,
  abstained, model not run; retain eight evidence rows.
- [ ] Uncheck eDNA and repeat. Expect a source-disabled limitation. Set k=1 with
  both enabled; expect incomplete coverage and retained available evidence.
- [ ] Clear all sources and ask. Expect `no_sources_selected`, no retrieval/model.
- [ ] Inline research-card actions retain explicit source/analysis scope. Where
  no real published research analysis exists, verify a safe scope/unavailability
  limitation; do not invent a live scientific-answer pass.
- [ ] Submit clearly marked QA answer feedback. Admin later verifies saved scope,
  final coverage, reason and model state; legacy snapshots still render safely.
- [ ] Privileged review controls and admin navigation are unavailable. Direct
  `/api/backend/admin/feedback` access is denied. Direct review POST attempts
  must also be denied by the server, not inferred from hidden UI buttons.
- [ ] Check another account's known QA interaction feedback endpoint: 404 with
  no existence disclosure. Own completed interaction feedback remains accessible.
- [ ] Sign out and re-enter; role and saved source preferences remain correct.

## Researcher session

Sign out, then use an existing invited researcher's normal Google account.

- [ ] Verify Data/review access and absence of administrator controls.
- [ ] In Data → Research reviews, paste the private synthetic packet and create
  a draft. Verify cited definition, current-evidence preview and empty-rationale
  disabled approval. Enter “DISPOSABLE QA ONLY; no scientific approval.”
- [ ] Approve one synthetic draft and reject a separate draft with a QA rationale.
  Verify immutable review history and version/state transitions.
- [ ] Replay a decision with the prior version/hash through the authenticated
  browser's normal API: expect 409, unchanged state and no extra event. Use
  ordinary session credentials; never mint internal tokens or impersonate roles.
- [ ] Attempt `/research-registry-reviews/{id}/apply` with current version/hash:
  researcher must receive 403. Verify administrator-only API denial separately.
- [ ] Check saved Chat scope/coverage, cross-user feedback isolation and re-entry.

Direct POST acceptance can be performed by the user in browser developer tools
with normal same-origin authenticated requests. Do not extract authentication
cookies or secrets into shell scripts. Record actual HTTP status and bounded error
code, not just screenshots of unavailable controls. Agents using read-only browser
evaluation cannot fabricate a direct POST pass.
